目标不是“页面越多越好”，而是：
* 每个后端接口都有合理前端承载
* 区分“需要独立页面的资源”和“只需要按钮/弹窗/抽屉的动作”
* 让论坛前端既**干净**、**有学术社区气质**，又**具备管理与运营能力**
* 方便你后续继续拆给 AI 做 Vue3 页面

1. **整体前端信息架构**
2. **完整前端路由设计**
3. **逐个后端模块对应的前端页面与交互**
4. **每个核心页面该长什么样**
5. **哪些接口不该做独立页面，而该做弹窗/抽屉/组件**
6. **前端权限、路由守卫、状态设计**
7. **推荐的前端目录结构**

# 一、整体前端信息架构

你的论坛不是传统“首页全是列表”的贴吧式产品，也不是电商式大杂烩首页。
它更适合做成一种 **“知识社区壳 + 空间页 + 内容详情页 + 管理后台”** 的结构。
我建议前端分成 **4 个布局层（Layout）**：

## 1. PublicLayout：游客可访问

用于承载公开内容：

* 首页
* 登录/注册
* 分类/空间广场
* 空间详情
* 帖子详情
* 资源详情
* 用户主页
* 搜索结果

这个层最重要的任务是：
**让未登录用户也能看懂这个论坛在讨论什么，并且看到高质量内容。**

---

## 2. AppLayout：登录后主站壳

用于承载用户自己的使用空间：

* 我的首页 / 信息流
* 发帖 / 编辑帖
* 发布资料 / 编辑资料
* 我的通知
* 我的主页 / 我的帖子 / 我的收藏 / 我的空间订阅
* 个人设置 / 隐私设置

这个层最重要的是：
**让一个学生登录后，能快速找到“我关注的课”“我发的贴”“我收藏的资料”。**

---

## 3. ModLayout：版主/审核员工作台

用于承载治理与审核：

* 举报处理
* 待审核帖子
* 待审核资料
* 审核操作日志
* 某空间的版主管理页

这个层不是给普通用户看的，它应该更“工具化”，更偏列表、筛选、批量操作。

---

## 4. AdminLayout：管理员后台

用于承载平台级管理：

* 用户管理
* 角色管理
* 信任等级/限制管理
* 分类管理
* 标签管理
* 空间管理
* 系统状态概览

这个层视觉上应该更像“运营后台”，而不是社区前台。

# 二、完整前端路由设计

下面是我建议的完整 Vue Router 路由结构。
我先给你“用户能看懂”的路径树，再给你每一组路由的设计逻辑。

---

## 1) PublicLayout 路由

```text
/
├─ /login
├─ /register
├─ /explore
│  ├─ /explore/categories
│  └─ /explore/spaces
├─ /search
├─ /spaces/:spaceId
│  ├─ /spaces/:spaceId/posts
│  ├─ /spaces/:spaceId/resources
│  ├─ /spaces/:spaceId/rules
│  └─ /spaces/:spaceId/moderators
├─ /posts/:postId
├─ /resources/:resourceId
└─ /users/:userId
```

---

## 2) AppLayout 路由

```text
/app
├─ /feed
├─ /posts/new
├─ /posts/:postId/edit
├─ /spaces/:spaceId/resources/new
├─ /resources/:resourceId/edit
├─ /notifications
├─ /me
│  ├─ /me/overview
│  ├─ /me/posts
│  ├─ /me/comments
│  ├─ /me/resources
│  ├─ /me/bookmarks
│  ├─ /me/spaces
│  ├─ /me/reports
│  ├─ /me/settings/profile
│  └─ /me/settings/privacy
```

---

## 3) ModLayout 路由

```text
/mod
├─ /mod
├─ /mod/reports
├─ /mod/review/posts
├─ /mod/review/resources
├─ /mod/actions
└─ /mod/spaces/:spaceId
```

---

## 4) AdminLayout 路由

```text
/admin
├─ /admin
├─ /admin/users
├─ /admin/users/:userId
├─ /admin/users/:userId/permissions
├─ /admin/users/:userId/restrictions
├─ /admin/roles
├─ /admin/categories
├─ /admin/tags
└─ /admin/spaces
```

---

## 5) 可选但不必单独页面的路由

以下能力后端有接口，但前端**不一定非要给独立页面**：

* `polls`
* `files`
* `post subscriptions`
* `resource feedback`
* `report creation`

这些更适合做成：

* 帖子详情页里的区块
* 弹窗
* 抽屉
* Dropdown 菜单动作
* 右侧边栏面板

# 三、逐个后端模块，对应哪些前端页面与交互

下面我按你后端的 router 模块来推前端承载。

---

# 1. system.py → 前端承载方式

后端接口：

* `GET /api/v1/health`

## 前端不需要独立页面

这个接口不应该给普通用户做单独页面。

## 前端应该怎么用

它应该用于两处：

### A. 应用启动时的全局健康探测

场景：

* 前端初次启动时检测后端是否在线
* 后端挂了时，显示统一“服务暂时不可用”的空白页或降级提示

### B. 管理后台首页的系统状态卡片

路由：

* `/admin`

显示：

* API 状态：正常 / 异常
* 最近检查时间
* 版本号

---

# 2. auth.py → 前端承载

后端接口：

* `POST /auth/register`
* `POST /auth/login`
* `GET /auth/me`

## 对应前端路由

* `/login`
* `/register`

## 页面设计

### `/login`

布局：

* 居中窄卡片
* 左边是品牌介绍/插画，右边是登录表单（大屏）
* 小屏幕就只保留表单

表单字段：

* username
* password

交互：

* 登录成功后：

  * 若之前访问的是受保护页，则返回原页
  * 否则默认去 `/feed`
* 底部提供“没有账号？去注册”

---

### `/register`

表单字段：

* username
* email
* password
* confirm password

交互：

* username/email 实时基础校验
* 注册成功后可直接跳 `/login` 或自动登录

---

### 顶部全局登录状态

任何页面都应在右上角展示：

* 未登录：登录 / 注册按钮
* 已登录：头像、通知、发帖按钮、用户菜单

这部分依赖 `GET /auth/me`

---

# 3. me.py → 前端承载

后端接口：

* `GET /me`
* `PATCH /me/profile`
* `PATCH /me/privacy`
* `GET /me/stats`
* `GET /me/notifications`

## 对应前端路由

* `/me/overview`
* `/me/settings/profile`
* `/me/settings/privacy`
* `/notifications`

---

## 页面设计

### `/me/overview`

这不是传统“个人主页展示页”，而应该是“我的控制台”。

页面结构建议：

#### 顶部用户信息卡

显示：

* 头像
* 昵称 / 用户名
* 角色 badge
* trust_level badge
* reputation_score
* 学校显示状态

#### 中部统计区

调用 `GET /me/stats`
显示：

* 发帖数
* 评论数
* 上传资料数
* 收藏数
* 关注空间数
* 获赞数

#### 下部快捷入口

* 我的帖子
* 我的评论
* 我的资料
* 我的收藏
* 我的举报
* 设置

---

### `/me/settings/profile`

表单字段对应：

* nickname
* avatar_url
* bio
* school_name

交互：

* 头像上传可走 `files` 模块
* 成功后局部刷新顶部个人信息

---

### `/me/settings/privacy`

表单字段：

* school_visibility
* allow_anonymous_post

交互重点：

* 如果 `trust_level < 3`，前端 UI 就直接把 `hidden` 选项置灰
* hover 或说明文字提示：
  “达到可信等级 3 后可隐藏学校信息”

---

### `/notifications`

这是单独页面，不建议只做顶部下拉。

页面布局：

* 左侧：通知类型筛选（全部、回复、@我、点赞、审核、举报结果）
* 中间：通知列表
* 顶部：未读数 + “全部标记已读”

同时顶部铃铛可以做成：

* hover/dropdown 预览最近 5 条
* 点击“查看全部”跳 `/notifications`

---

# 4. users.py → 前端承载

后端接口：

* `GET /users/{user_id}`
* `GET /users/{user_id}/posts`
* `GET /users/{user_id}/comments`
* `GET /users/{user_id}/resources`

## 对应前端路由

* `/users/:userId`

## 页面设计

这个页面应该是**公开主页**，不需要做成“社交化主页”，而是做成“贡献档案”。

### 页面结构

#### 顶部用户头部

* 头像
* 昵称
* 用户名
* 个人简介
* 学校（按 visibility 控制）
* trust_level
* reputation_score
* 注册时间

#### 下方 Tabs

* 发帖
* 评论
* 资料

### 为什么不拆成多个路由

`/users/:userId/posts` 这种可以做，但前期没必要。
你更适合用**一个页面 + Tab 切换**，减少页面数，提高一致性。

显示：

* 当前空间信息

* 关注按钮

  * 帖子
  * 资料

默认是帖子流

### 右侧：上下文面板

显示：

* 空间简介
* 版主列表简版
* 空间规则摘要
* 置顶公告/导读贴
* 快速发帖 / 快速上传资料按钮

---

## `/explore/spaces`

这是空间广场页。

结构建议：

### 顶部筛选条

* 分类筛选
* 类型筛选（course/school/interest）
* 搜索框
* 排序（最热 / 最新 / 资源最多 / 关注最多）

### 主体

空间卡片列表，每张卡显示：

* 空间名
* 类型 badge
* 描述
* post_count
* resource_count
* subscriber_count
* 进入按钮
* 已关注状态

---

## `/spaces/:spaceId/posts`

页面内容：

* 顶部：空间头部
* 次级 Tab：全部 / 提问 / 资源贴 / 经验 / 公告 / 投票
* 列表项使用 `PostCard`

顶部按钮：

* 发帖
* 发布导读贴（如果有权限）
* 排序切换

---

## `/spaces/:spaceId/resources`

页面内容：

* 资料搜索/筛选
* 资源类型筛选（真题/讲义/笔记/作业/答案）
* 资料卡片列表

每个资源卡片显示：

* 标题
* 类型
* 作者
* 版本数
* 下载数
* 收藏数
* 标签
* 创建时间

右上角：

* 发布资料

---

## `/spaces/:spaceId/rules`

设计成简洁的说明页

* Markdown 渲染
* 顶部显示最近更新时间
* moderator/admin 可见“编辑规则”按钮

---

## `/spaces/:spaceId/moderators`

这是对外公开版主信息页
显示：

* 版主头像、昵称
* 任命时间
* 是否 owner

---

## `/admin/spaces`

后台空间管理页
更像表格：

* 名称
* 类型
* 分类
* owner
* 状态
* 帖子数
* 资料数
* 关注数
* 编辑 / 冻结按钮

---

## `/mod/spaces/:spaceId`

这是版主工作台
内容包括：

* 空间概览
* 规则编辑

# 8. posts.py → 前端承载

后端接口：

* 关注空间
* 推荐
* 最新

右边栏可以放：

* 我关注的空间
* 未读通知摘要
* 我的统计

---

## `/posts/:postId`

帖子详情页是论坛的核心页面。

### 页面结构

#### 顶部面包屑

分类 > 空间 > 帖子标题

#### 主内容区

* 标题
* 作者
* 发布时间
* 标签
* 内容 Markdown
* 状态标签：

  * 已解决
  * 已锁定
  * 置顶
  * 精华

#### 帖子操作条

* 点赞
* 收藏
* 订阅
* 举报
* 编辑（作者）
* 删除（作者/管理）
* 置顶/加精/锁帖（版主）

#### 如果是 question

显示“最佳答案卡片”

#### 下方评论区

* 评论输入框
* 评论列表
* 回复树
* 评论点赞
* 选为最佳答案按钮（作者/版主）

#### 右侧边栏

* 作者信息卡
* 所属空间信息
* 相关标签
* 同空间相关帖子
* 若为资源贴，可显示相关资料

---

## `/posts/new`

发帖页一定要做成**表单型创作页**，不是只有一个 textarea。

字段：

* 标题
* 空间
* post_type
* 标签
* 正文 Markdown
* 是否匿名

如果 `post_type = poll`
则底部显示投票选项编辑器。

右侧可做一个“发布前检查”栏：

* 标题是否为空
* 是否选择空间
* 是否选择类型
* 是否含标签
* 预览模式切换

---

## `/posts/:postId/edit`

和新建页复用同一个 `PostEditorView`
仅在初始化时加载详情。

# 四、每个核心页面具体应该怎么设计

下面我把最重要的页面进一步细化成前端结构。这个部分最接近你真正要交给 AI 生成 Vue 页面。

---

# 1. 顶层壳设计（全站统一）

## Header

所有前台页面共用：

* 左侧：Logo + 当前入口
* 中间：全局搜索框
* 右侧：

  * 发帖按钮
  * 通知铃铛
  * 用户头像菜单

用户菜单：

* 我的主页
* 我的帖子
* 我的收藏
* 设置
* 退出登录

---

## 左侧侧边栏（仅 AppLayout / 部分详情页）

显示：

* 我关注的空间
* 空间分类快速入口
* 最近访问
* 快捷创建（发帖/上传资料）

---

## 右侧上下文栏

根据页面变化：

* 在空间页：空间简介 / 规则摘要 / 版主
* 在帖子页：作者 / 相关帖 / 操作
* 在资源页：下载统计 / 反馈摘要
* 在 feed 页：我的统计 / 推荐空间

---

# 2. PostCard 设计

这是论坛最核心的列表组件。

一张帖卡建议包括：

* 标题
* 摘要
* 作者
* 所属空间
* 标签
* 状态 badge：

  * question / guide / experience / resource / poll
  * 已解决
  * 精华
  * 置顶
* 底部统计：

  * 浏览
  * 评论
  * 点赞
  * 收藏
* 右侧更多菜单：

  * 举报
  * 收藏
  * 订阅

视觉上不要像旧论坛纯文本列表。
应该是**清爽卡片 + 足够留白 + 标签与状态清晰**。

---

# 3. ResourceCard 设计

资料卡应该与帖子卡区分开，避免混淆。

一张资源卡显示：

* 标题
* 资源类型
* 描述摘要
* 作者
* 所属空间
* 版本数
* 下载数
* 收藏数
* 反馈概况

资源卡比帖子卡更强调“可用性”和“版本信息”。

---

# 4. 用户等级与身份显示设计

你提到等级与学校显示限制，所以前端必须有清晰身份体系展示。

建议统一做这些 badge：

* `RoleBadge`
* `TrustBadge`
* `ReputationBadge`
* `SchoolVisibilityBadge`

显示规则：

* 在用户卡、帖子作者栏、评论作者栏里轻量显示
* 不要太抢眼，但要可读

比如：

* `Lv.2`
* `已认证版主`
* `高信任用户`

---

# 五、哪些接口应该是按钮/抽屉/弹窗，而不是页面

这一步非常重要。
很多人做论坛会把所有功能都做成页面，结果前端非常碎。

---

## 应该做成弹窗的

### 举报

用 `ReportDialog`
触发点：

* 帖子更多菜单
* 评论更多菜单
* 资料更多菜单

---

## 应该做成抽屉的

### 管理后台里的用户详情

* 从 `/admin/users` 列表点进去可抽屉或独立页
* 若你想提效，抽屉比跳页更好

### 举报详情

在 `/mod/reports` 中适合右侧抽屉查看

---

## 应该做成嵌入组件的

### 评论点赞 / 回复

### 帖子点赞 / 收藏 / 订阅

### 投票

### 资料反馈

### 关注空间

---

## 不用做页面的

### 文件详情

### 点赞列表

### 单独的 solution 页面

### 单独的 bookmark 页面（合并进我的收藏）

# 六、前端权限、路由守卫、状态设计

前端不是安全边界，但要有清晰的 UX 控制。

---

## 1. 路由 meta 建议

每条路由加这几个 meta：

```ts
meta: {
  title: '页面标题',
  requiresAuth: true,
  roles: ['admin', 'moderator'],
  trustMin: 2,
  layout: 'app',
  keepAlive: false
}
```

---

## 2. 权限分层

### 游客可访问

* 首页
* 搜索
* 空间详情
* 帖子详情
* 资源详情
* 用户主页
* 分类/空间广场

### 登录可访问

* 发帖
* 收藏
* 评论
* 通知
* 我的页面
* 举报
* 关注空间

### trust_level 限制

* `trust_level >= 2`：

  * 创建空间
  * 上传资料
  * 匿名发帖
* `trust_level >= 3`：

  * school_visibility 可设置 hidden

### moderator/admin 才能访问

* `/mod/*`

### admin/super_admin 才能访问

* `/admin/*`

---

## 3. 前端必须处理的页面状态

每个页面至少考虑：

* loading
* empty
* error
* not found
* no permission
* pending review / hidden / locked 等内容状态

比如帖子详情页：

* 帖子不存在 → 404
* 帖子被隐藏 → 提示“该内容已不可见”
* 帖子锁定 → 评论框禁用并说明

---
